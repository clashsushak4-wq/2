# Навигация по скиллам и MCP — проект Telegram trading-бот

## Слэш-команды
* /grill-me — использовать перед крупными архитектурными решениями (например, смена структуры локализации, новая система premium-эмодзи), не для мелких правок.
* /goal — для автономных многошаговых задач (рефакторинг, багфиксы). Ограничения по MCP — см. Global, раздел 5.
* /schedule — для фоновых задач бота (пинг Telegram API, проверка логов). Не создавать расписания с интервалом чаще, чем раз в 5 минут без явного запроса.

## Автовыбор скиллов по контексту
* Вопрос по Telegram Bot API (кнопки, custom emoji, keyboards, локализация) → сначала Context7 MCP для актуального синтаксиса API, потом код.
* Вопрос про архитектуру/избыточный код → ponytail-audit / ponytail-review.
* Вопрос про безопасность бота (хранение токенов, обработка апдейтов, инъекции) → security-auditor.
* auditing-wallet-security — НЕ использовать на реальных кошельках в рамках этого проекта без явного запроса; если бот работает с тестовыми/mock-данными — можно свободно.

## MCP для этого проекта
* **Разрешены свободно (read-only):** Context7 (документация Telegram Bot API, актуальные библиотеки), Playwright (если есть веб-админка бота — проверка UI), memory-mcp-server (граф зависимостей модулей бота).
* **С подтверждением:** postgres-mcp-server, если бот использует БД — любые write/migrations; github-mcp-server — PR можно открывать, merge вручную.
* **Не использовать в этом проекте:** oci-mcp — бот не работает в Oracle Cloud, этот MCP здесь не нужен вообще; если появится необходимость — обсудить отдельно перед подключением.

## Специфика проекта (контекст для агента)
* Стек: Windows + WSL2/Docker, изолированные контейнеры под ИИ-агентов.
* Бот: разделы Profile, Education, Trading, Information, Admin Panel.
* Технические детали Bot API (custom emoji ID, blockquote-цвет через MTProto, link preview) — см. память по проекту / предыдущие обсуждения, не переизобретать заново.
